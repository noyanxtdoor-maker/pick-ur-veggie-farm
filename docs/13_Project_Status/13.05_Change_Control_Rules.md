# 13.05 — Change Control Rules

## Rules
- Do not redesign a locked module unless a critical flaw exists.
- All changes must be additive unless approved otherwise.
- Preserve backward compatibility.
- Document the reason for every major change.
- Review impact on accounting, inventory, and audit logs before modifying workflows.

## Approval Standard
A change may be made only after:
1. Problem identification
2. Risk analysis
3. Design review
4. Approval
5. Controlled update
