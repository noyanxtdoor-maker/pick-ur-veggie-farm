# Offline Synchronization Rulebook

## Purpose

PickUrVeggie ERP V3 is designed for island farms and remote areas where internet connectivity may be unstable.

The system must continue operating even when there is no internet connection.

Offline capability is a convenience feature, but the cloud database remains the final source of truth.

---

# Offline First Philosophy

The system follows:

Field Activity

↓

Local Device Record

↓

Offline Sync Queue

↓

Internet Available

↓

Supabase Validation

↓

Permanent Database Record

---

# Source of Truth Rule

Mobile devices are temporary data collectors.

They are NOT the master database.

The official company record exists only after successful synchronization with Supabase.

---

# Offline Allowed Activities

The following can be performed without internet:

Farm Operations:

- Time in and time out
- Task updates
- Production activities
- Fertigation records
- Irrigation records
- Harvest recording
- Pest observations
- Photos and notes

Inventory:

- Material usage
- Stock counting
- Inventory requests

Employee:

- Leave requests
- Cash advance requests
- Personal notes

Equipment:

- Maintenance records
- Equipment inspection

IoT:

- Sensor data buffering

---

# Offline Restricted Activities

The following require internet and server verification:

Financial:

- Payroll approval
- Payment verification
- Accounting period closing
- Journal approval

Security:

- Role changes
- Permission changes
- User activation or termination

System:

- Company settings
- Backup settings
- Critical configuration changes

---

# Offline Record Identity

Every offline record receives:

- Local temporary ID
- Device ID
- User ID
- Creation timestamp
- GPS location (if permitted)

After synchronization:

- Local ID links to permanent database UUID

---

# Conflict Detection

The ERP never silently overwrites records.

Example:

Worker A:

Records harvest:
100 kg

Offline.

---

Worker B:

Records the same harvest:
100 kg

Online.

---

System response:

- Detect possible duplicate
- Preserve both records
- Create conflict notification
- Require supervisor review

---

# Device Time Trust Rule

Device clocks can be manipulated.

Therefore the system stores:

- Device time
- Server synchronization time
- Time difference

Sensitive actions may require supervisor review.

---

# Offline Storage Policy

Only necessary information should be stored locally.

Examples:

Allowed:

- Assigned tasks
- Current crop information
- Required SOPs

Restricted:

- Entire accounting database
- All employee salaries
- Company confidential reports

---

# Synchronization Queue Status

Every offline transaction has a status:

Pending

Waiting for internet.

---

Uploading

Currently sending data.

---

Successful

Accepted by the server.

---

Conflict

Requires human review.

---

Failed

Could not synchronize.

---

# Synchronization Failure Rules

If synchronization fails:

- The local record is not deleted
- The user receives notification
- The system retries automatically
- Manual review is available

---

# Device Loss Scenario

If an employee loses a phone:

- Device trust is revoked
- Future synchronization is blocked
- Company data is removed according to security policy
- Audit record is created

---

# Offline Security Principle

Convenience must never destroy data integrity.

The system should allow workers to continue working while protecting company information.

---

# Final Offline Principle

The farm should never stop because the internet stopped.

However, no offline action should bypass:

- Security
- Permissions
- Audit trails
- Financial controls
