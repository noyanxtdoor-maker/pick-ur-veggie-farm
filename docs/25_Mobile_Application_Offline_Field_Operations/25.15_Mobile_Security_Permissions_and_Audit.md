# Mobile Security, Permissions and Audit

## Purpose

The mobile application provides access to sensitive company information.

Every action must follow the same enterprise security standards as the main ERP.

---

## Role-Based Access Control

Mobile permissions follow the user's ERP role.

Examples:

Farm Worker:

Access:
- Assigned tasks
- Personal attendance
- Relevant SOPs

No access:
- Company financial reports
- Other employee salaries
- Administrative settings

---

Supervisor:

Additional access:

- Team information
- Task approvals
- Operational reports

---

Owner and Administrator:

Access according to their assigned permissions.

---

## Security Logging

The ERP records:

- Login events
- Logout events
- Device registrations
- Failed access attempts
- Sensitive data access
- Important approvals

---

## Sensitive Operations

High-risk activities may require additional verification.

Examples:

- Changing security settings
- Viewing confidential financial reports
- Approving payroll adjustments

---

## Data Protection

The mobile application protects data using:

- Encryption
- Secure communication
- Permission validation
- Session controls

---

## Audit Integrity

Records must be traceable.

The system must answer:

- Who performed the action?
- When did it happen?
- Which device was used?
- What information changed?

---

## Principle

Mobility should increase convenience without reducing accountability.
