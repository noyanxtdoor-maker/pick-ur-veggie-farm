# Worker Task and Daily Operations Interface

## Purpose

The worker interface is the most frequently used screen in the entire mobile application.

Its design determines whether employees will actually use the ERP.

---

# Daily Home Screen

Example:

Good morning Juan 🌱

Time-In:
07:00 AM

Today's Assignment:

1. Harvest Eggplant Tunnel A

[Start Task]

2. Prepare Nutrient Solution

[Start Task]

3. Clean Water Filter

[Start Task]

---

# Task Workflow

Simple workflow:

Receive Assignment

↓

Start Task

↓

Perform Work

↓

Record Results

↓

Submit Completion

---

# Task Information

Each task may include:

- Task description
- Location
- Crop or equipment involved
- Required materials
- Instructions
- Expected completion time
- Priority level

---

# Task Status

Examples:

🟢 Not Started

🟡 In Progress

🔵 Waiting for Review

✅ Completed

---

# Quick Action Buttons

Examples:

Record Harvest

Report Problem

---

# Problem Reporting

Workers can quickly report:

- Pest issues
- Equipment failure
- Low inventory
- Safety hazards
- Crop abnormalities

A report may include:

- Description
- Photo
- Priority level

---

# Codex Worker Assistance

Workers can ask:

"Codex, how do I perform this task?"

Codex provides:

- SOP instructions
- Safety reminders
- Required materials
- Best practices

---

# Productivity Philosophy

The worker should spend time farming, not operating software.

The mobile application should remove paperwork and simplify field reporting.
