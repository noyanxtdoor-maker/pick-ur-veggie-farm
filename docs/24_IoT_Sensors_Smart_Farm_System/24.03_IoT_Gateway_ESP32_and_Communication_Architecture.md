# IoT Gateway, ESP32 and Communication Architecture

## Purpose

Sensors usually cannot communicate directly with the ERP.

An IoT gateway collects sensor information and securely transfers it to the digital system.

---

## Typical Architecture

Temperature Sensor

↓

ESP32 Controller

↓

WiFi Network

↓

Internet

↓

Supabase IoT Database

↓

PickUrVeggie ERP

↓

Codex Analysis

---

## Why ESP32?

ESP32 is recommended because it is:

- Low cost
- Energy efficient
- Reliable
- Widely available
- Supported by a large developer community

---

## Communication Methods

Version 1 supports:

- WiFi

Future versions may support:

- LoRa
- Cellular networks
- Other industrial communication systems

---

## Data Transmission

The gateway sends:

- Device ID
- Timestamp
- Sensor value
- Measurement unit
- Battery status (if available)
- Signal quality

---

## Communication Failure Handling

If internet is unavailable:

ESP32 stores temporary readings.

↓

Connection returns.

↓

Stored data synchronizes with the cloud.

---

## Security Requirements

Communication must support:

- Device authentication
- Secure data transmission
- Unauthorized device blocking

---

## Reliability Principle

A sensor that occasionally disconnects should not cause the entire farm system to fail.
